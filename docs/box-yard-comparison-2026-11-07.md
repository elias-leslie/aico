# Aico vs Box Yard (2026-11-07)

Assessed at aico 3e05a608 (working tree has unrelated edits) and box-yard 3ed69f4 (shallow clone, read only, never installed or run). Box Yard claims below come from its README, `AGENTS.md`, `docs/` and `server/` source. Its "verified against real services" section (README, 2026-10-22) is the author's own claim; I did not check it.

## What Box Yard is
Box Yard (github.com/AgentSystemLabs/box-yard, MIT, TypeScript) is a chat-first web app that runs a "yard" of headless Claude Code agents. You talk to a Coordinator, which routes to one Captain per project, which starts tasks. Each task runs `claude -p --resume` once per message, in an Upstash box, Docker, a GPU pod, an SSH machine or a local folder (README "How it works", "Tasks and turns").

Overlap with Aico: the same owner problem (many agents, one person, phone access, keep going when the laptop is closed, ask the owner questions, track quota and spend, remember things per project). The architecture differs at the root: Box Yard owns a headless agent loop and puts a chat UI on top; Aico owns real interactive terminal sessions (Tether, tmux, cgroups) and puts a viewer and an inbox on top.

## Differences

| Area | Box Yard does | Aico does | Recommend | Why |
|---|---|---|---|---|
| Agent runtime | One headless turn per message, `claude -p --session-id` then `--resume`; Codex and Cursor via adapters (`server/tasks.ts`, `server/codex.ts`, `server/cursor.ts`, `runner/box-runner.mjs`) | Real interactive TUIs and shells in tmux, owned by Tether; Claude Code, Codex, Antigravity, Pi (`packages/tether`, README) | Ours | Keeps slash commands, interactive prompts, live typing and any harness that has no headless mode. Box Yard gets clean structured events (cost, rate limits, session id) because it owns the loop; Aico already reads those from the agents' own files and hooks (`agent-state.md`) |
| Surviving restarts and crashes | Turns run detached; `run.json` records pid + boot id + start time so a recycled pid is never mistaken for the turn; interrupted turns retried up to 2x with a "you were interrupted" message; Coordinator and Captain turns run inside the server and are lost on restart (README "Restarts and upgrades") | Per-pane cgroup scopes, generation fencing, announced crash recovery and reboot restore with the agent's own resume id (`packages/tether/docs/crash-recovery.md`, `reboot-continuity.md`) | Ours | Ours is stricter and covers the coordinator too. The pid+boot+start-time identity check is the same idea we already have as generation fencing |
| How coordination works | Coordinator and per-project Captain are server-run Claude sessions with MCP tools `create_task`, `send_to_task`, `wait_for_tasks`, `create_tasks` (up to 100) (`server/mcp.ts`, `captains.ts`) | A coordinator is an ordinary agent session; lanes launched with `st aico create`; lane reports (finished/blocked/ended) with floors and doubling quiet periods; `st aico watch` (`lane-reports.ts`) | Ours | No custom orchestrator process to keep alive, and any harness can coordinate. Box Yard's wake rules (FYI marker, "when unsure, wake", loop guard in `server/loopGuard.ts`) are the same problem we already solved with the lane-report floors |
| Task model | DB-backed status machine (queued, starting, working, needs_input, waiting, idle, pr_ready, done, failed), priority, slot queue; only the owner marks done | Session state working/idle/blocked, Finished group, ROADMAP.md plus `st` tasks; admission by memory pressure, no queue | Ours | One owner with a handful of agents does not need a slot queue. "Done is only ever the owner's mark" is worth keeping in mind for the Finished group |
| Where work runs | Upstash boxes (pool, auto-sizing), Docker, Daytona, RunPod, Vast, SSH machines with labels, this computer (`server/providers/*`, `server/machines/*`) | Workstation, Proxmox host, VMs and CTs over the Fleet link (TLS 1.3, Ed25519 allowlist, wake-on-create) (`docs/fleet-link.md`, `hub/wake.ts`) | Ours | Own hardware, no rented compute, no cloud keys. Theirs is better only if you ever want burst GPU or a box that outlives the workstation, and that adds spend and credentials |
| Isolation | Cloud boxes are isolated; local and SSH tasks are explicitly unsandboxed | cgroup containment per pane; no sandbox by owner decision | Ours | Same trust model for local work; nothing to copy |
| Admission and cleanup | Fixed slot counts per box/computer, disk-free checks, cleanup of finished tasks' build output that never touches a folder a process still uses or one with unpushed work (README "Local runner") | Pressure-based admission (MemAvailable, PSI, host-steward verdict) (`agent-admission.ts`) | Ours, with one idea from theirs | Pressure beats fixed counts. Their "never delete a folder anything has open or that holds unpushed work" rule matches our own cleanup rule; keep it explicit if we add task folders |
| Protecting work in progress | After every turn, pushes the branch plus uncommitted and untracked files to a hidden ref `refs/boxyard/wip/<task>` on origin, never touching the task's index or HEAD; archives as the fallback (README "Nothing gets lost") | Machine-level: Btrfs snapshots, restic, T7, Drive, recovery drills; sessions resume from agent files; repo copies to the peer host are on the roadmap | Mix | Theirs is cheap, per-task and fine-grained, and fits our "failover: copy active repos to the peer" item. Push to the peer host, not GitHub (publishing needs your approval) |
| Switching harness when a limit hits | "Continue with..." on a failed or resting task: same task, branch and workspace, new CLI session seeded with a bounded recap, never resumes another CLI's session (`docs/task-continuation.md`) | Model-switch detection, `models route` facts (what each subscription has left), refusal reasons incl. `used_up`; no one-click handoff of a live session to another tool | Theirs | Real gap. When Claude is used up you currently start a new session by hand and re-brief it |
| Model and effort routing | YAML rules (fallback, defaults, per-project, semantic rules) put in the Coordinator's prompt; precedence list; model/effort/rule recorded per turn (`docs/routing.example.yaml`, README "Model/effort routing") | Roles and launch policy rows in context.db; `route()` returns facts only, the coordinator chooses; used-up providers skipped in chains (`packages/context/src/route.ts`, `packages/agent/src/rules.ts`) | Ours | Rows in one database, fed by live quota, beat free-text rules the model has to interpret. Recording the route per turn is something we do (`model-record.ts`) |
| Subscription limits | Per-login 5h/weekly windows from `rate_limit_event` and Codex rollout files; "unknown is not zero"; round-robin across several logins (`docs/limits.md`, `docs/logins.md`) | `packages/usage`: readings with as-of time, credit lots and plans, pace and days-left, refusals; Quota page; one central logins store with audit and timed reveal | Ours (rotation optional) | Ours also tracks credits and refusals. Automatic round-robin only matters if you hold several subscriptions of one provider; skip unless that changes |
| Spend tracking | Every run's tokens and cost in SQLite, charged as the step from the session's previous reported total (so resumes are not double counted); daily charts by model, project, task, role; compute estimated per box; optional budgets that hold new turns (README "Usage and costs") | Daily rows and a Status spend card; spend per day per provider is an open item (#24) | Mix | Take the per-project/role attribution and the "step from previous total" rule. Skip the budget gate that stops turns: subscriptions already enforce limits and you do not want a second brake |
| Owner alerts | Browser notifications, spoken replies (TTS), toasts (`server/tts.ts`, README "Spoken replies") | FCM push to the Android app only, outbox, deadman from the Proxmox sender; Needs you inbox (`packages/notify`) | Ours | Works when the browser is closed and is the owner's stated channel. Voice is not wanted |
| Asking the owner | `ask_user` shows in the task chat and the sidebar's Waiting on you; the Coordinator relays | `tether ask` with options, recommendation, blocking flag, shared files on the card | Ours | Richer and shows in one inbox. Nothing to copy |
| Remote access and auth | Built-in password (15+ chars, leaked-list check, throttling, 90-day cookie), Host and Origin checks, binds 0.0.0.0 once a password is set, LAN and Tailscale URLs (`server/auth.ts`, `password.ts`, `commonPasswords.ts` is 20k lines) | Loopback only; Cloudflare Access token re-verified at the origin; Host and Origin guard (`web-server/src/access.ts`, `docs/remote-access.md`) | Ours | Matches your "phone via Cloudflare Access only" and is far less code. Their password machinery is over-built for one owner |
| Secrets in transcripts | Known secret values and private-key blocks are redacted from stored transcripts, tool output and errors (`server/redact.ts`); tokens encrypted at rest and passed by reference | Secret-looking strings are masked in previews only (`packages/shared/src/secrets.ts`); the Recent transcript is not redacted; a Telegram token showed in a note preview (recommendation #4) | Mix | Keep our shape-based masking, add value-based redaction from the logins store for transcripts shown in Recent and History |
| Identities | Per-project GitHub identity (tokens, git author, signing key, Claude login, allowed runners); Coordinator can be limited to "status only" per project | One owner, one account; agents run with the owner's CLIs | Ours | Solves a multi-account, client-work problem you do not have |
| Git and pull requests | First-class: `create_pull_request`, live PR state injected on resume, merge button, hooks on `pr_ready`, branch naming that follows repo convention (`server/prs.ts`, `branchNames.ts`) | Direct commits to main via `st commit`, local checks, publication separate and owner-approved (`packages/checks`) | Ours | Solo flow on main does not need a PR lifecycle. Revisit only if repos start taking PRs |
| Scheduling | Cron schedules start an agent task (or a Coordinator prompt) with catch-up and overlap skipping; QStash wakes a paused box (`server/scheduler.ts`) | `packages/jobs`: daily or every-N-minute jobs with leases, a home machine and workers, running a command; session wakes paste a note into an idle session (`wakes.ts`) | Ours | Leases and home placement are what failover needs. A scheduled agent prompt can already be a job whose command is `st aico create` |
| Event-to-action hooks | Hooks on task events send a template prompt to a task, Captain or Coordinator, with filters and fire caps (`server/hooks.ts`) | Lane reports and wakes; no owner-configurable event rules | Ours (for now) | Useful when you run dozens of PRs; at your scale lane reports cover it and caps would be ceremony |
| Agent-to-agent messages | `message_agent`, `message_captain`, `fyi: true` flag that records without waking, rate limited | Session sends, lane reports, handshakes via `st` | Ours | Equivalent. The FYI flag is a nice touch if lane noise becomes a complaint |
| Project memory | Curated notes injected into every agent; agents only suggest, the Captain resolves each suggestion at PR merge | `st memory` and context.db: scoped memories, prompts, roles, budgets delivered per session (`packages/context`) | Ours | Same idea, ours is scoped and budgeted. The "agents suggest, a curator resolves" step is already how memory is saved here |
| Context and compaction | Context meter in every header; Compact button and auto-compact for Coordinator and Captains that first writes a durable summary file per compaction | Context fill badge in the session header; compaction left to the agent CLI | Ours | Both show fill. Durable pre-compaction summaries are covered by memory and plan docs |
| UI model | Chat-first: Coordinator chat, Captain and task panels over SSE, queued messages with Cancel/Undo, Stop, Steer, dictation, command palette, lightbox (`web/src/components/*`) | Session-first: xterm.js terminals with a phone keyboard, Needs you, Recent transcripts, Status, Files, Notes | Ours, borrow reading | A terminal is the right view of an interactive agent. For reading replies on a phone, their chat rendering is nicer; our Recent/History transcript view (#25) is the place for it |
| State storage and code shape | One SQLite (`server/store.ts` 4.5k lines, `tasks.ts` 9.3k, `mcp.ts` 3.5k) | Small per-concern databases and JSON contracts (`contracts/`, context.db, usage.db, status.db) | Ours | Smaller seams are easier for agents to change safely. Their file sizes are the warning sign |
| Testing | Fast/slow tiers with a machine-wide lock, `test:related` from the diff, and a scripted fake Claude (`scripts/fake-claude.mjs`) that drives the whole app with triggers like `[ask]`, `[fail]`, `[hang]` | `st check`, package tests, Tether lifecycle harness (shells and a real-agent smoke that submits no prompt), live Haiku testers | Mix | The scripted fake agent makes Needs you / Finished / stuck states reproducible. We have none |
| Backup of the tool's own state | Snapshots its own box every 6 hours, keeps 3 | Full backup and recovery system with drills | Ours | Not comparable in depth |

Areas with no real overlap, so not compared: Box Yard's Gmail/Notion/Linear connectors, spoken replies, Upstash/Daytona/RunPod/Vast billing, GitHub identity sealing; Aico's Status page, backups and recovery, notes and capture, Android app pairing, Proxmox power actions, Neri hunter placement.

## Worth adopting (up to 5)

1. **Continue a session on another harness with a bounded recap** (medium). Add "Continue with..." to the used-up banner and to a Recent row. Tether starts a new session in the same project and branch for the chosen tool, seeded with the original brief, branch, last summary and recent turns, and never resumes the other CLI's session. Lands in `packages/tether/src/sessions` (recap from the existing readers), `packages/context` `route()` for the choices, and the session header in `packages/web-frontend`. Reference: `docs/task-continuation.md`.
2. **Per-session safety copy of uncommitted work** (medium). After each idle edge, write the branch plus uncommitted and untracked files to a hidden ref (`refs/aico/wip/<session>`) without touching the index or HEAD, and ship it to the peer host over the Fleet link. Lands as a job in `packages/jobs` plus a small helper in `packages/ops`, and is the first piece of the roadmap's failover item. Do not push to GitHub.
3. **Redact known secret values in transcripts** (small). Extend `packages/shared/src/secrets.ts` so values held in the logins store are replaced in transcripts the web server serves for Recent and History, alongside the existing shape-based masking. Closes recommendation #4's transcript side.
4. **Spend attribution by project and role, counted as steps** (small to medium). In `packages/usage`, record each run's cost as the difference from the session's previous reported total so resumed sessions are not double counted, and tag rows with project and role; show on the Quota page and in `aico usage show` (recommendation #24). No budget gate.
5. **A scripted fake agent for tests** (medium). A small program that behaves like Claude Code or Codex enough for Tether (state files, hook reports, an ask, a finish, a crash) and is driven by trigger words in the prompt. Lands under `packages/tether/src/test-fixtures` plus a web-server test, and gives deterministic coverage for the "session state tells the truth" fixes (recommendation #1).

Not adopting: the password and lockout system, identities, PR lifecycle and hooks, cloud box pools, spoken replies, budget-gated queues, the single large database.
