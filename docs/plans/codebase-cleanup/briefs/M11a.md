# M11a brief (builder: Codex gpt-6.1-sol xhigh, Aico lane; owner approved 2026-11-03)

Goal: first half of milestone M11 in /srv/workspaces/projects/aico: the fleet link. Each machine has its own Ed25519 key, connects out to its peers over one long-lived encrypted connection, and is trusted only when its key is on a pinned allowlist the owner approved. The link replaces the SSH-based hub link in `packages/fleet` and `packages/tether/src/hub`. M11b (secrets folder, tool logins over the link, signed updates, re-enrolling the 14 hosts) is a separate brief; don't start it.

State: npm workspaces under `packages/`. Each package.json carries `aico.layer` and `aico.imports`; depcruise enforces them against a known-violations baseline. `node scripts/check-stages.mjs` regenerates the quick stages. M1 added `packages/store` and `packages/status`: Status rows are written over the loopback HTTP API, and `st status` reads them. A machine's id in Status rows and on the allowlist is its lower-cased short hostname, e.g. `davion-sidarli`; `next_run` is required on kind=machine rows. Re-read M1's report in `briefs/` or `git log` for the exact API. aico-web listens on 127.0.0.1:3002, and tether@default is the live daemon; restarting it keeps tmux sessions alive.

Scope:
1. `contracts/fleet-frames.schema.json` plus drift fixtures covering hello, auth, control, event, sync and a terminal-view frame. The TS code tests against them.
2. Machine identity: an Ed25519 key per machine, kept 0600 in the Aico state dir, never printed or committed.
3. Pinned allowlist: approved peer public keys plus machine names, held by every machine.
4. Enrollment: a new machine shows a short code; the owner approves it with an Aico Needs-you ask (`tether ask create`; the tray and phone take over in M4). Approval adds the key to the allowlist.
5. The link: one outbound, long-lived, mutually authenticated encrypted connection per peer pair. Use pinned keys with Node's built-in crypto/TLS, no CA and no new crypto library unless Node lacks a primitive; say which you used and why. It carries control, events, terminal views and row sync. It reconnects with backoff, and the only liveness signal is real silence (no app-level timeouts beyond a dead-connection bound).
6. Listener: LAN only, never bound on a public interface. Declare it with `nightshift declare --host davion-sidarli --what listener --hours 24 --reason '<what and why>'`, and the same on each host you start it on. Nothing reaches our hosts from the internet except through Cloudflare.
7. Move the existing hub's users (placement, wake, peer HTTP calls, notes row sync) onto the link. SSH stays only as the owner's manual rescue route. No code path may depend on SSH.
8. Status rows: one per machine link (state, last seen, meaning, action), written through the M1 writer.
