# M1 brief (builder: Opus 5.5 high, native subagent)

Goal: milestone M1 of the codebase cleanup in /srv/workspaces/projects/aico: the Status row contract that every later milestone reports into, the `status` package that stores and serves rows, a loopback HTTP write API, `st status` / `aico status`, a Python writer helper, and the late/unknown rules. No Status screen (that is M2, after an owner mockup review). This is a contract others build on: get the shape right and keep it small.

Read first (the spec): `docs/plans/codebase-cleanup/plan.md` "Settled consolidation choices" -> "Status: one screen for the whole fleet" (~L232-246, the row fields, late/unknown, actions, UI rule) and the decisions log; `cutlist.md` 1.1 (layers: `shared` 0, `store` 1, `status` 2; one DB file per owning package; contracts/ is data every language tests against), 1.2-1.4 (boundaries, checks, deploys), the M1 row in section 4, and 2.2/2.3 rows whose replacement says "status" (what will write rows later: checks, jobs, backups, services, VMs, machine links, grants, repo status).

State after M0a/M0b: npm workspaces `packages/{shared,tether-client,fleet,notes,tether,web-server,web-frontend,ui-kit}`, `native/{host-steward,pve-sender}`, `contracts/`. Each package.json has `aico.layer` and `aico.imports` (the allowed @aico imports); `.dependency-cruiser.cjs` enforces them; `scripts/check-stages.mjs` generates per-package quick stages into `.st-check.toml` (rerun it after adding a package; boundaries.mjs fails when the block is stale). `node:sqlite` is used directly by tether and web-server today (baselined violations; don't migrate them in M1). aico-web listens on 127.0.0.1:3002 (unit `scripts/systemd/aico-web.service`). `st aico` / `st tether` resolve to aico executables through the summitflow tool registry (see summitflow commit 0a15d63f5 for where).

Scope:
1. `contracts/status-row.schema.json` + replay fixtures (valid and invalid rows, late and unknown cases) that the TS package and the Python helper both test against. Row: stable id (writer-chosen key), what, kind, machine, project (optional), state, last run, next run / expected cadence, meaning (plain words), action(s) (run now / detail / log / look into it as data, not UI), updated-at. Keep fields to what the plan names; justify any addition.
2. `packages/store` (layer 1): the only code that touches `node:sqlite` for new packages: open, WAL, simple versioned migrations. Just what `status` needs; no ORM, no FTS yet (M6 adds FTS5 when it needs it).
3. `packages/status` (layer 2): owns `status.db`; upsert from writers, rollup (problems first, healthy folded into a count), reader with filter (state, kind, machine, project, search) and sort. Late rule: a row past its expected next run shows "late since <time>". Unknown rule: rows of a machine whose own machine row is late show "unknown" (not ok, not failed). Unknown is never zero/ok.
4. Loopback HTTP API in web-server: write (upsert rows, loopback only, refuse non-loopback) and read (list + rollup) endpoints; web-server links `status`. No new auth scheme; follow how web-server guards its existing loopback-only routes.
5. CLI: `st status` (and `aico status` if there's a natural home; no `cli` package yet, that is M10d) printing the rollup and filters; plain owner-facing copy (problems first, healthy count). Route it the way `st aico` is routed; don't build a CLI framework.
6. Python writer helper (stdlib only, posts to the loopback API, fails soft with a logged error) where host-steward can import it; tested against the contract fixtures. A Go helper waits for M7 (its first caller); say so in the report.
7. One real writer to prove it live: the `aico-notes-export` timer run and `aico-web` itself report rows (e.g. a self-row per service on start/heartbeat), so `st status` shows real data and a late row when a run is overdue.

Rules: run `node scripts/check-stages.mjs` after adding packages; `aico.imports` per the 1.1 table; exact-pinned deps. Proof: `st check --acceptance` before and after (pytest 789, Vitest 2615 passed / 6 skipped before; new tests added on top), iterate with `st check --quick --changed-only`. Deploy with `st service rebuild aico --detach` (check `st sessions may-disrupt` first; restarting tether is safe), then live: POST a row over loopback, see it in `st status`; non-loopback write refused; the notes-export row appears after `systemctl --user start aico-notes-export.service`; a row with a past next-run shows late. Record measured `st check` quick times for status/store edits.

Commits: a few checkpoints, `st commit -m "..." --paths <files>`, message ending "Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>". Hold the repo while editing shared files (`st lease --hold "M1 status"`), release at the end. Never git stash, reset, checkout or rebase. Never open /srv/workspaces/projects/neri or hunting/case data; never read credentials, .env or auth files. Lean: no extra layers, no speculative fields, no UI. If a contract choice is genuinely the owner's, take the smallest option and list it.

Report (<= 30 lines): commits (full SHAs), packages/files with LOC, the row schema fields, live checks done, test counts before/after, quick-check times, choices made and anything undone.
