Scope:
1. Session store in Tether's SQLite. Keep only what a reader needs:
   - per session: tool, model, project, start and end, outcome;
   - token totals (input, cache read, output; Pi totals included);
   - files written and a tool-call count.

   The data starts fresh (ah-05 says one cut-over copy at most). Don't migrate the event store.
2. One transcript reader per tool, for Claude Code JSONL, Codex rollout files and Pi sessions:
   - reads incrementally;
   - survives a file being rewritten;
   - never loads a whole large file into memory.
3. `aico sessions list|show|events` CLI, plus a session-events dump (JSON) for debugging.
4. web-frontend: recent sessions and one transcript view. Use the existing Aico design, matching the product standard, with honest loading, empty and failed states. Run uilint on the rendered page.
5. Point the callers of Agent Hub's session APIs that Aico or tools still use at Tether's store. Find them with rg in aico, summitflow and claude-config. Leave Agent Hub's own ingestion running until M12, and say what still uses it.
