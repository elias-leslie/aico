# One-time archive verification

The sealed archive is `/srv/workspaces/archive/pre-aico/`. Its `manifest.json` lists the size and SHA-256 of every other archive file. `protection.json` in this evidence folder records the manifest's own digest, complete checksum readback, permissions and immutable flags. Archive payloads are kept out of Git.

`scripts/archive-pre-aico.py` takes the adjacent `config.json` and a stage (`capture`, `finish_capture`, `verify`, `seal`). The stages ran in root systemd units with nice 19, memory high 4 GB, and NVMe read/write limits of 150/100 MB per second. PostgreSQL's throwaway container used no network, two CPUs and a 3 GB memory limit. Long disk work ran outside the short heavy-work admission lane, as the managed tools recommend.

Each database capture used one exported repeatable-read, read-only transaction. Counts, JSONL exports and custom-format compressed dumps shared that snapshot. Agent Hub's main dump retains the `session_events` schema; its separate dump contains that table's data. Verification restored main pre-data and data, then separate event data, then main post-data, with errors fatal. It compared every public table's count with its captured live source count. Tables excluded for credentials were required to restore empty. Both restores passed, including all post-data constraints. Dump TOC listings remain inside the archive. The throwaway container and its anonymous scratch volume were removed.

The coordinator explicitly approved opaque copying of the entire database archive, including any Neri session rows, with counts/checksums only. No session payload was queried or inspected. The `api_keys`, `credentials` and `remote_hosts` tables retain schemas but omit data. A separate remote-host metadata JSONL omits `token_hash`; clients have no secret/hash columns and remain in the main dump. Agents and all 1,351 versions also have JSONL exports; their line counts match their source snapshot. Five evaluation READMEs dated October 22/27 and all three workflow examples were copied.

SQLite stores used the online backup API, incorporating committed WAL data, followed by `integrity_check`. Their restore counts are recorded as metadata; PostgreSQL counts are compared with the exact source snapshot. Copied trees and named Nightshift files were independently compared with their live sources by SHA-256. The ledger's 7,043 consecutive links were recomputed; both recorded PVE anchors matched the chain and the copied PVE append-only anchor list.

Agent Hub's `local_history` automation profile originally had `enabled=true`, `clock_owner=central`, no separate legacy control row and no active pruning run. Only its enabled flag was paused, before capture. It stayed paused through successful restore verification, then returned to its original state; all three Agent Hub services remained active. `retention-verification.json` records the before/during/after states.

The first root-run capture could not resolve the user's authenticated PVE SSH setup. Completed database dumps and file copies were retained. The PVE hop was changed to use the existing kasadis SSH connection; `finish_capture` completed missing file stages without another database dump. Independent review reproduced a defect in the new resume path: an existing partial tree could be skipped. Two regressions failed first; the fix fills missing files, validates existing files without replacing them, and refuses conflicting content. The reviewer independently reran both tests and closed the finding. The actual archive's complete source checksum comparison had already passed.

All archive files and directories have no write bits and have Btrfs immutable flags. A second SHA-256 pass matched every manifest entry before protection was recorded. Existing whole-volume native and Drive coverage includes this ordinary directory under `/srv/workspaces`; no source or retention change was needed. The manual native run preserves backups, and the manual Drive run skips retention. `backup-proof.json` records the fresh backup points and small-file restoration result.

OmniNull's evidence replica stays at its existing location. Its existing whole-volume backup coverage and the `ominull-production-state` source carry the replica and CT 150 respectively; no additional one-time archive is made. The existing CT 150 backup preparation supplies `lxc-150.tar` and its separately encrypted secrets archive. Regenerable receipts in `.git/st`, graph cache, isolated observations and old release builds are omitted as the cutlist directs. No manual data, backup or snapshot pruning was performed.

The Nightshift declaration covered the temporary pruning change, local throwaway runtime and archive protection. No persistent service unit was stopped, disabled or changed, so no service rollback is required. There was no deployment: this checkpoint contains the one-time script, configuration, regression tests and evidence only.
