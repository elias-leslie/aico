# M11c Codex review

Reviewed the brief and both owner addenda against the working Logins implementation on 2026-11-04. This is a source review of the in-progress change; the findings below need regression tests and resolution by the implementing lane. No production secret, auth file, Neri repository, Neri data or hunting session was opened. No product files were edited. No broad gate was run.

1. **Secret-bearing child errors escape sanitization.** `packages/fleet/src/logins-cli.ts:236` returns `io.execute(...)` without awaiting it inside the surrounding `try`. The default executor can reject when `spawn` validates a NUL-containing environment value; its TypeError includes that value. `packages/web-server/src/main.ts:248` then logs the raw Error. A synthetic-only Node probe confirmed both `rejectedOutsideSanitizer: true` and `errorContainsValue: true` without printing the value. Regression: store a synthetic value containing NUL, run with an otherwise valid child, assert a sanitized nonzero result and no value in stderr or rejected error. Both normal and lab execute calls need the same boundary.

2. **A role revoke does not revoke the default wildcard.** `packages/fleet/src/logins.ts:366` removes only the named role, but newly stored entries have `roles: ['*']` and `allowed` accepts that wildcard at line 183. Regression: set an API key with defaults; revoke `research`; use as `research` must fail. Current code still authorizes it.

3. **Tool-login machine access controls do not govern delivery.** The page and CLI machine-grant actions invoke `pushLoginGrants`, but `packages/fleet/src/logins-delivery.ts:19` excludes all entries with `tool`; `pushToolLogins` still selects by the separate `peer.tools` field (`secrets.ts:107`). Regression: grant a stored Pi login to an approved peer through the new store/page API, assert the peer receives it; revoke the same machine, assert its copy is removed. Neither action changes the legacy peer-tool grant today.

4. **A delivered login cannot be revoked.** `packages/fleet/src/logins-delivery.ts:66` uses `store.remove` to remove omitted fleet entries; `packages/fleet/src/logins.ts:378` refuses every entry with a source, including `fleet:sender`. Regression: receive one valid synthetic entry, then receive the same sender's empty snapshot; the second call must succeed and remove its file/index entry. Current code throws and retains the value.

5. **Recipient grant metadata stays stale after delivery.** `receiveLoginGrants` passes updated entry metadata to `store.set`, but `packages/fleet/src/logins.ts:311` prefers `old.machines` and `old.roles` whenever an entry already exists. Regression: receive roles `['*']`, then receive an update with roles `['implementation']`; a research caller must be refused. Current receiver retains `['*']`. Role changes also do not trigger delivery from the new CLI/API (only machine changes do).

6. **The index filename can be used as a login name.** `packages/fleet/src/logins.ts:47` accepts `index.json`. `set('index.json', syntheticValue, {}, owner)` writes the value onto the index path, then overwrites it with the metadata commit and reports success. Regression: reserved names must fail before any write; ordinary names must preserve their exact values.

7. **The existing tool launcher bypasses role/machine grants.** `packages/fleet/src/secrets.ts:84` reads every matching tool file directly rather than applying the new store's caller checks. `tether fleet tool` uses this helper (`packages/tether/src/fleet-cli.ts:81`). Regression: with a stored Claude token and hunting/recon/verification caller metadata, tool environment injection must refuse before reading the value; a permitted caller should still work.

Contract gap: Agent Hub's lab `PATCH` route merges selected fields, removes selected fields and optionally changes expiry, while retaining all other fields. Its storage code preserves account username/password during a patch and requires the password again when a login URL changes origin. The reviewed Aico surface has full-bundle replacement only. The parent lane should port the used partial-edit behavior or explicitly resolve this scope gap with the coordinator; a full replacement is not the same contract.

Coverage limits: no migration, deployed page, screenshots, fleet link, owner reveal, default get-output destination or final gate result was verified in this review. Parent lane owns those proofs. The current `get` output check also treats any pipe/socket as safe; an agent tool's captured stdout is commonly a pipe, so default `get` should be exercised through the actual agent-shell logging path before claiming the no-session-log requirement.

## Follow-up: full peers and worker copies

The coordinator changed the design after the initial review: full peers accept writes and converge through per-entry versions/tombstones; workers retain granted copies and send writes to a full peer. This bounded pass reviewed `LoginStore.snapshot`/`mergeSnapshot`, delivery, the new client and async CLI wiring. The local `update-signing-key` exception was supplied explicitly by the parent. This section describes the working source observed during this pass; the earlier findings above are historical and are not a claim that later fixes failed.

Executed three small synthetic runtime probes through `st tools run`. Each bundled only the relevant module into memory, used temporary directories and fixture strings, printed booleans/counts only, and removed its temporary data. No real secret or deployed store was accessed.

1. **Worker RPC is refused by the real fleet role gate.** `logins-client.ts:163` sends an exec request, but `fleet.ts:336` allows worker peers to open only sync/jobs channels. Thus worker RPC writes never reach `loginRpc` through a real link. Current client tests mock `requestExec`, bypassing that gate. Add a synthetic transport check from a worker pin to a full peer; permit only the intended scoped Logins RPC, preserving the general worker exec refusal. This is a source finding, not a live fleet test.

2. **RPC responses above 4096 characters are truncated.** `LoginClient` parses `requestExec.stdout` as complete JSON (`logins-client.ts:187`); `exec.ts:115` keeps only its last 4096 characters. The actual `requestExec` probe sent a 6022-byte synthetic JSON response through a temporary Unix socket and returned `remoteExit: 0`, `receivedChars: 4096`, `jsonReadable: false`. A modest login list, audit list or large permitted value therefore fails. The response mode needs a bounded complete payload instead of a log tail.

3. **Stale worker snapshots delete newer entries.** `logins.ts:656-658` unconditionally discards every previously replicated entry absent from a received worker snapshot, regardless of its version or source. A worker first receiving a newer granted entry from full A, then an older empty snapshot from full B, loses that newer entry. The synthetic probe confirmed `workerHadNewerEntry: true` and `staleOmissionDeletedIt: true`. Grant removals need versioned revocation information, rather than unversioned omission overriding newer state.

4. **Stale worker assignments overwrite newer assignments.** The `|| !snapshot.full` branch at `logins.ts:694` disregards assignment versions on workers. The same probe applied an assignment at revision 200, then an empty assignment at revision 100; `staleAssignmentReplacedNewer: true`. This can restore a previously removed target as well as remove a newer grant. Compare versions for worker assignment updates too; projection changes need their own versioned representation.

5. **Merged state is not forwarded to already-connected downstream peers.** A local write pushes snapshots in `loginRpc`; link-ready pushes through the existing `pushToolLogins` wrapper. `receiveLoginGrants` only merges. In an allowed A↔B↔worker topology, an A write reaches B but is not delivered onward to its already-connected worker; the same ordering can occur when B catches up after its worker reconnects first. Add a synthetic three-node catch-up test proving the worker receives merged grants without another unrelated write or reconnect. This is a source finding; no real topology was changed.

6. **The excluded local system key is still writable through Logins.** Snapshot/discovery exclude `update-signing-key`, but `set` accepts its name. The synthetic probe confirmed `localSystemKeyAcceptedByLogins: true` and `butExcludedFromSnapshot: true`. A new Logins set can overwrite and index the system key despite the explicit “outside Logins” exception. Reject `policy.localFiles` at the write/name boundary, before touching a file.

Supported checks: two full peers writing the same entry at the same logical timestamp converged through the node tie-breaker; a newer deletion tombstone blocked resurrection by an older full snapshot. Both synthetic probes passed. The CLI normal and lab execute branches now await execution within the sanitizer. No final acceptance gate, worker live RPC, deployed UI or real offline catch-up was verified by this reviewer.

## Implementing lane resolutions

All seven initial findings and all six replication findings have regression coverage. The source quick gate passed with 461 related tests after the fixes. Concrete red runs preceded the access, revocation, index-name, child-error and replication fixes; managed real-fleet tests also cover worker scope binding, a response larger than 4096 bytes, and forwarding a full-peer merge to an already-connected downstream worker.

- Child execution is awaited inside the sanitizer, including the default NUL-containing environment failure. `get` accepts only an owned 0600-style regular output file; captured pipes and sockets are refused.
- Explicit role denials override wildcard access. Existing tool launchers use the same caller/grant checks. Tool entries and grants use the common index and snapshot transport.
- Full peers use entry revisions and tombstones. Worker revocations carry versions; stale omissions do not delete newer entries, stale assignments cannot roll back newer assignments, and stale values cannot resurrect a revoked copy.
- Full-peer merges forward only when their state changes, including onward to connected workers. Workers use a dedicated Logins channel, preserve complete bounded replies, cannot send snapshots or assert owner authority, and retain the existing refusal for generic worker exec.
- Peer authority comes from the local root-owned pin role. A mode environment variable cannot promote a pinned worker. The release signer is rejected at the name/write boundary and omitted from indexing/sync.
- Lab partial edits preserve account fields, protect site/password changes, and keep other fields. Scope also prevents a lab enrollment from changing a tool's auth destination; field selection uses own fields rather than inherited object properties.

Final committed acceptance, deployment and live evidence are recorded separately in the lane's verification/report files; these statements do not claim a real secret was revealed in a screenshot.
