Reviewed 2026-11-05 04:12 UTC against `briefs/M10d-2.md`, the full M10d cut-list row, and the relevant plan requirements. Read-only product review; only this report and `review-focused.txt` were written. The checkout also contains M10d-1 work, which was excluded.

Changes required at the reviewed snapshot:

1. **P1 — Item 4 still does not judge the inputs of the stages that ran.** `packages/checks/src/commit.ts:119` fingerprints only the selected commit files and compares only those files again at lines 139 and 146. A declared stage may read other inputs. `run.ts:299` computes its reuse key before execution, and `run.ts:361` stores a successful result without comparing the inputs afterward. Reproducer to add: a stage for `src/a.ts`, with `inputs = ["src"]`, reads `src/b.ts`, signals that read, then waits; change `b.ts` before releasing it. Committing `a.ts` must refuse that stale proof, while an otherwise identical concurrent edit outside the stage inputs must succeed. The newly added concurrent-commit test proves unrelated commits can proceed, but does not exercise this input-change boundary. This is an existing limitation of the canonical Aico implementation, now relevant because the old ST implementation is being retired; it is not a newly introduced regression.

2. **P1 — Item 3 initially covers managed lanes but misses native background subagents.** `packages/tether/src/lane-reports.ts:661` builds its roster exclusively from Tether sessions and lane cursors. Native Claude subagent starts/completions do not create either. Consequently a native background subagent can disappear without ever becoming a child in pulse or the new hook endpoint. Required regression: start a synthetic native background agent via the real hook event shape, omit its completion, restart/resume the coordinator, and assert its started-but-unfinished state and evidence age are shown. The parent confirmed that the coordinator explicitly included both native background subagents and managed lanes, and is implementing this addition. No timeout should be used as proof of death, and the display must remain report-only.

3. **P2 — Item 2 requires ownership before a root can retire, and the new callback uses a wrong tool name for Claude.** `packages/tether/src/agent-state.ts:343` is the only new producer of `History.bind`, after the periodic process probe obtains a signal. `daemon.ts:318` then calls `endOwned`, which updates only existing owner records (`history.ts:204`). A root ending before its first successful probe has no record and remains open. Already-ended pre-migration lanes also have no owner record; replaying their retirement ids at startup does not populate one. The test manually calls `bind` first and therefore cannot expose these cases. Add an integrated fast-retirement test and verify the originally reported ended Codex lane after deployment. Separately, the callback passes `adapter.harness`; Claude's harness is `claude` (`adapters/claude-code.ts:558`), but its transcript keys use `claude-code`, so those bindings never match. Use the adapter's history/tool identity and test that boundary.

4. **P2 — Pairing must carry the existing external-link allowlist.** `packages/web-server/src/config.ts:353` defaults the new pairing's origins to Aico alone; `Pairing.issue` adds the phone API origin. Legacy pairing includes the configured `OPEN_ORIGINS`. Android filters both notice links and action buttons against the origins saved by pairing (`native/android/.../model/Origins.kt`, `model/Models.kt`, `push/OpenLinkActivity.kt`). Re-pairing through the new page therefore drops other products' links unless deployment explicitly carries the previous configured list. Add a synthetic external-product-origin assertion and preserve the existing configuration, without printing its secret-bearing neighboring settings. The parent acknowledged this migration step.
